# Microsoft Store package (MSIX)

Every stable release publishes `eullm-windows-x64-store.msix`, built by the
`build-windows-msix` job in `.github/workflows/release-engine.yml` from the
two Windows ZIPs of the same release:

| Command | Build | For |
|---|---|---|
| `eullm` | CPU (`cpu\eullm.exe`) | every x64 Windows |
| `eullm-cuda` | CUDA 13.1 (`cuda\eullm.exe`) | NVIDIA RTX 3000/4000/5000, driver 580+ |

Both builds carry the Visual C++ runtime DLLs next to the exe. Both commands
also appear in the Start menu ("EuLLM" and "EuLLM (NVIDIA GPU)").

The package is **unsigned**. The Microsoft Store signs it after
certification, so it cannot be double-clicked to install as it is. It is
meant to be uploaded to Partner Center, not handed to users.

## Files

- `AppxManifest.xml`: identity (`I3KTechnologies.EuLLM`, publisher
  `CN=5FB2EAD6-A516-4F4B-A336-3E816A215B99`) as assigned by Partner Center
  to the reserved "EuLLM" product. The version is set by the release job
  from the tag (`EuLLM-v0.7.9` → `0.7.9.0`).
- `Assets/`: tile and Start menu icons, generated by `make-icons.py`.

## Try it locally before submitting

An unsigned package can be registered from its unpacked files once
Developer Mode is on (*Settings → System → For developers → Developer
Mode*). In PowerShell:

```powershell
Copy-Item eullm-windows-x64-store.msix eullm-store.zip
Expand-Archive eullm-store.zip -DestinationPath "$env:LOCALAPPDATA\eullm-msix-test"
Add-AppxPackage -Register "$env:LOCALAPPDATA\eullm-msix-test\AppxManifest.xml"

# Open a new terminal, then:
eullm --version
eullm-cuda --version

# Remove it again:
Get-AppxPackage I3KTechnologies.EuLLM | Remove-AppxPackage
```

## Submit to the Store

In Partner Center, *Apps and games → EuLLM → Start submission*. The text for every field is in [`store-listing.md`](store-listing.md); in short:

1. **Pricing and availability**: free, all markets.
2. **Properties**: category *Developer tools*.
3. **Age ratings**: fill in the questionnaire.
4. **Packages**: upload `eullm-windows-x64-store.msix` from the release.
5. **Store listings**: description, at least one screenshot, search terms
   (e.g. local AI, offline LLM, Ollama compatible, GGUF, private AI).
6. **Submission options → Notes for certification**: explain the
   `runFullTrust` capability, which the Store asks about for every desktop
   app. For example: *"EuLLM is a Win32 console application (a local LLM
   inference server). runFullTrust is required to run its classic desktop
   executable. It is used from a terminal through the `eullm` and
   `eullm-cuda` execution aliases; `eullm serve` starts a local HTTP API on
   localhost:11434."*

Each later release produces a new `.msix` with a higher version: upload it
in a new submission.
